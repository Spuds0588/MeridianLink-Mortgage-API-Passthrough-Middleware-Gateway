A small, stable API in front of MeridianLink Mortgage.

An open-source, stateless middleware template that turns MISMO 3.4 XML into clean JSON, masks borrower NPI per persona, queues fee writes through a FIFO pipeline, and onboards title, broker, and appraisal partners with role invite links. It deploys into the lender's AWS account and never stores loan documents.

This project improves when deployments report back

This is an independent, community-supported template, not a vendor product. The maintainer has no MeridianLink access and no AWS account for this project, so real-world validation only happens when someone who can deploy tells the rest of us what they saw. Bugs, MISMO shape corrections, and fixes are a shared responsibility.

File them as GitHub issues or pull requests with sanitized evidence (redacted field shapes, deployment or log excerpts), never secrets or PII. Privately-patched forks are discouraged, and no one should claim live MeridianLink or AWS verification that did not happen.

What it does

MISMO to JSON

Reads return loanId, milestone, property, terms, fees, and persona-permitted extras. No vendor-side XML parsing.

Persona masking

Deny-by-default allowlists per role. SSN, credit score, and income never reach a title or appraisal key. Unknown personas fail closed.

Async fee writes

PATCH /v1/loans/{id}/fees returns 202 with a job ID, retries record locks with backoff, and dead-letters after five attempts.

Invite onboarding

The lender shares a title, broker, or appraisal link. The gateway locks the key to that persona server-side; the client cannot choose it.

Field discovery

GET /v1/fields?ids=... proxies MeridianLink definitions and caches them per persona for five minutes.

One-file deploy

A single CloudFormation template under the direct-upload limit with the Lambda bundle inlined. No S3 bucket, no zip, no build step in AWS.

Deploy in one line

Run this in AWS CloudShell. It verifies your session, asks for the MeridianLink base URL, username, and password, generates three role invite codes, and deploys the stack with a VPC, NAT gateway, and static egress IP.

bash <(curl -sSL https://raw.githubusercontent.com/Spuds0588/MeridianLink-Mortgage-API-Passthrough-Middleware-Gateway/main/deploy.sh)

It prints the gateway URL, portal URL, health and fields URLs, the static egress IP, and one invite link per role. Share each link only with that role's partners; invite codes are bearer secrets.

Ask MeridianLink support to allowlist the printed StaticEgressIp before expecting live reads or writes to succeed.

API at a glance

MethodPathPurpose
GET/healthUnauthenticated health check
GET/portal?role=title&code=...Persona-locked invite page and field cheat sheet
POST/portalProvision a key with role, code, tenantName, email
GET/v1/fields?ids=11,646Field definitions from MeridianLink
GET/v1/loans/{id}Masked MISMO-to-JSON read
PATCH/v1/loans/{id}/feesQueue fee updates, return 202 and a job ID
GET/v1/jobs/{id}Job status, owner only

All /v1/* routes require x-api-key. The portal and health check are the only unauthenticated HTTP routes. Job states: PENDING, RETRYING, COMPLETED, FAILED.

Verify locally before you deploy

npm run dev       # fake MeridianLink + local gateway on :3000
npm run verify    # template sync check + full test suite
npm run build     # regenerate dist/gateway.js and template.yaml

No dependencies to install. The local stack runs the real handler against a fake MeridianLink and an in-memory AWS stand-in, including the invite portal, masking, schema cache, and lock-retry behavior. Mock loans: ML-998822, ML-LOCKED-1, and ML-404.

Common questions

Does the gateway store loan data?

No. It stores tenant mappings, job status with a TTL, and the in-flight fee payload in the queue message. Loan documents and borrower data stay in MeridianLink, which remains the system of record.

Can I try it without MeridianLink or AWS access?

Yes. npm run dev and npm test run the real handler against a local fake, with no accounts required. What that cannot prove is live authentication, real MISMO shapes, AWS resource behavior, or the egress allowlist.

How do I report a bug or become a contributor?

Open a GitHub issue with a minimal reproduction, sanitized evidence, and the commit you tested. Submit fixes as pull requests with a regression test and updated docs. Say so if you want to keep contributing: the maintainer is happy to add contributors. Never include client secrets, API keys, invite codes, loan data, or PII.

What has not been verified?

A real CloudFormation deployment, API Gateway key creation, DynamoDB and SQS behavior, live MeridianLink authentication, loan reads and writes, the static egress allowlist, and real MISMO response shapes. The template is structurally tested and the inline Lambda bundle is executed locally; that is different from a live tenant.

Can a broker submit a full 1003, upload borrower documents, or respond to conditions?

Partly. Broker keys can read identity, property, terms, conditions, and lock status, queue fee updates, and submit condition updates through POST /v1/loans/{id}/conditions; MeridianLink matches conditions by description, so only the changed rows need to be sent. Full 1003 sections and borrower document upload still have no write path: PATCH /v1/loans/{id} returns 501, and document routes are not implemented.

Why is the invite model role-scoped instead of open?

An open portal would let anyone mint a key into a lender's MeridianLink. Each invite code maps server-side to one persona, so a title partner cannot request broker scope, and the maintainer can rotate a role's code through stack parameters.
